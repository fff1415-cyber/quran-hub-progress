## السلوك

قبل POST يحفظ العميل معرفًا عشوائيًا وجسم الطلب الأصلي بما فيه `expected_assignment_id`. إعادة المحاولة تستعملهما بعد فقد الاستجابة أو تعذر التحقق أو إعادة تحميل الصفحة. تُجمع المسودات حسب المجمع والدور ومعرف الحساب الحاليين دون تعديل تسجيل الدخول أو الرمز أو الصلاحيات. لا يحفظ الرمز في المسودة؛ الحسابات القديمة بلا معرف موثوق تستعمل تجميعًا مجزأً للجلسة نفسها فقط، ولا يُستنتج ربط بين جلستين بالاسم.

يقفل الخادم الطالب كما كان، ثم يفحص الإيصال. الطلب الجديد يخضع لكل شروط التعيين والمسمّع واكتمال الحفظ الأصلية. يحفظ التعيين والطابور والإيصال في المعاملة نفسها، ويعلن النتيجة بعد الالتزام. لا يغير الإيصال إنجازًا قديمًا أو درجة أو فترة أو ملكية. إعادة الطلب المعروف تؤكد المعرف السابق دون تعيين آخر؛ لا تعيد نسخة قديمة من طابور السرد. `operation_probe` يبحث عن إيصال فقط ولا ينشئ تعيينًا أو إيصالًا.

تبقى مقدمات المصادقة والدور ونطاق الطالب والخطة قبل كل استعلام إيصال. الإيصال ليس إذنًا لتنفيذ انتقال جديد؛ المحاولة الجديدة تمر بالشروط الأصلية كاملة. استعمال معرف العملية لبيانات مختلفة أو إيصال تالف يفشل دون تغيير العمل.

لا تعتمد نتيجة الصفحة على الإقرار وحده؛ تطابق استمارة الطالب المعاد قراءتها معرف التعيين والخطة. إن تغير التعيين بعد تنفيذ طلب قديم، يوضح الخطأ ذلك ويحفظ المسودة بدل إعادة الطالب إلى الخطة القديمة. تبقى مسودات التبويبات متعددة الأجسام للمراجعة دون اختيار بحسب الساعة. لا تمنع مسودة ملتبسة لطالب تسجيل طالب آخر. يزال طلب النقل التقني بعد التأكيد والقراءة؛ سجل الطالب والخادم لا يحذفان. عند فشل التنظيف الجزئي يبقى معرف الإيصال الفائز آخر ما يحذف لضمان الاستئناف.

## القبول

المعالج الفعلي على SQLite وMySQL 8 وMariaDB 11.8، مع فقد استجابة وإعادة JSON بترتيب مختلف، ومعرف لبيانات مختلفة، وإيصال ناقص، وخطة أحدث يجب إبقاؤها، وأدوار مرفوضة ومعايير المسمّع الحالية. الاختبارات الفعلية لقيود قاعدة البيانات تثبت تراجع غلق الخطة والتعيين الجديد والطابور عند فشل الإيصال أو الطابور. اختباران متوازيان لنفس الهوية ينتهيان إلى تعيين واحد وإيصال واحد. يُختبر العميل الفعلي للتحميل/تجديد جلسة الحساب/النقر المكرر/فشل التخزين/تبديل الحساب/التنظيف الجزئي دون تأكيد محلي كاذب.

تبقى حزمة الحزم مقفلة وتثبت من الذاكرة السابقة فقط؛ لا تحديث للحزم. تقارن اختبارات النطاق المصدر كاملًا بعد استبعاد خطافات الإيصال المحددة، مع بقاء شروط الوصول وسائر مسارات البيانات حرفية. المقارنة مع تشخيصات TypeScript السابقة والبناء واختبارات الحزمة لا تغني عن هذه الحالات. لا تجارب على سجلات حقيقية، ولا اختبار متصفح كامل مدّعى.
