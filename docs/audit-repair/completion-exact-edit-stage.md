# F04 — تعديل الحفظ بمرجعه الصريح مع بقاء تاريخ التعديل

هذه متابعة معزولة لـ#42 المختبر عند `6da9dc3862a07eaea6614f0d065bfabe09f6684f`. تضيف دالة بيانات `plan_events_set_hifz` للإكمال/تعديل التاريخ/الإلغاء في مقطع معين، مع إيصال للعملية ومصدر متوقع صريح: event_id أو legacy_id مرتبط فعلًا بالتعيين، أو null لخلية قرأها العميل فارغة. المصدر الغائب عن سجل قديم لا يحوَّل إلى null بمعنى «فارغ» ولا يُستنتج من التاريخ.

لا توصل هذه المرحلة مسارًا عامًا أو صلاحية جديدة. شروط المشرف الخاصة بالدور وبداية السرد وبالتعيين الحالي ما زالت حرفية في API؛ يلزم إبقاؤها عند توصيل الدالة لاحقًا. مصدر الدرجة واليوم والفصل في الحمولة لا يُثبت ارتباط خلية تاريخية بمجرد إرساله؛ التوصيل الذري للدرجة لم يُنفذ بعد.

تعديل التاريخ يضيف حدثًا بتاريخ جديد وسابق سببي صريح، مع إبقاء الحدث السابق والصف الخام. الطلب الذي يستهدف حدثًا أقدم يُرفض بوضوح. إعادة الطلب المعروف بعد إلغاء أو نقل تعيين لا تعدل الكتابات اللاحقة. الإلغاء يضيف عكسًا؛ إزالة خلية فارغة مؤكدة أو تثبيت التاريخ نفسه لا يختلق حدثًا آخر. السجل NULL المبهم يبقى معروضًا ويُعلَّق تعديله وحده.

القبول: تشغيل الحالات نفسها على SQLite وMySQL 8 وMariaDB 11.8، مع حفظ التاريخين والمرجع السابق والقيم صفر/null والحقول المجهولة، وإعادة الطلب وفقد الاستجابة، والإلغاء/الإعادة، وبداية/تاريخ غير صالحين، وتعديل تعيين سابق. طلبان متزامنان مختلفان لخلية فارغة ينتجان حدثًا واحدًا وتعارضًا صريحًا للآخر. فشل الرأس يجهض الدرجة الاصطناعية المشتركة والإيصال والحدث. تبقى بوابات #40/#42 و#41 والبناء والتراجع فعالة؛ لا نجاح مدّعى قبل نتيجتها.

النشر والتفعيل معلّقان إلى موافقة إجراء قاعدة الإنتاج واكتمال الكاتب والقارئ والدرجة والعملاء. لا تسوية أو إعادة حساب أو نقل لبيانات قديمة، ولا تجربة على الطلاب. حزمة التراجع تحتفظ بهذه الطبقة؛ لا تستعاد قاعدة أقدم فوق كتابات جديدة. العطل في الطبقة المحتفظ بها يحتاج إصلاحًا أماميًا.

صُححت أيضًا وثيقة معالجة القديم لتسجل أن المستخدم حسم بقاء البيانات في صفحاتها ومخازنها المعتادة. خيار إخفاء القديم في عرض منفصل ملغى؛ ليس قرارًا مطلوبًا منه مرة أخرى. تبقى موافقات الترحيل والتسوية الفعلية وقواعد العمل منفصلة.
