# توصيل قارئ الإنجاز وعدّ اكتمال الخطة — متابعة F04/F20

الفرع `fix/audit-safe-completion-readers` يجمع checkpoint #40 عند `67791fd6a12800e49a44421d5c38c121e3e13748` مع الإصلاح المستقل المنشور #41 عند `ca3d341abc3d63e4c4110cef3c65bb51cf4c3c0e`، ثم يوصل القراءة وعدّ الحفظ فقط. **ليس جاهزًا للنشر أو إعلان اكتمال F04/F05.**

## النطاق

- ورقة الطالب القائمة تعيد نفس حقول الإنجاز من المصدر الفعلي للتعيين، مع مرجع حدث/سجل صريح فقط. لا تُعرض حمولة الدرجة الداخلية أو مرجع الفصل من مصدر مبهم.
- شرط اكتمال الحفظ للمسمّع وعداد تحديث المشرف يقرآن نفس رأس الإنجاز والتعيين ونطاق مقطع البداية. يظل الحفظ وحده معيار الاكتمال؛ لا تُضاف متطلبات ربط/مراجعة أو اجتياز أو دور جديد.
- عند غياب جداول الاقتراح، تبقى القراءة السابقة كما هي. عند وجودها، يبقى عرض التعيين القديم نفسه، بما فيه NULL غير المنسوب، ولا يُنسخ إلى تعيين جديد. الرأس الفاسد يسبب خطأ واضحًا دون تحويل التقدم لصفر أو إصلاح البيانات تلقائيًا.
- البداية غير الموجودة لا تعطي اكتمالًا، مطابقًا للتحقق الموجود أصلًا في `planHifzProgress`. لم تتغير هوية الطالب أو الخطة أو صلاحية أي حساب.

## القبول المعزول المطلوب

تشغيل معالِج ورقة الخطة الحقيقي لكل أدواره القائمة (المعلم والمساعد والطالب وولي الأمر والمشرف والمدير والمسمّع والسكرتير)، ومقارنة **المقطع نفسه** لا النسبة فقط. يشمل الإلغاء، وإعادة الخطة نفسها، والبداية من المنتصف، ورفض ولي أمر لطالب آخر ومعلم لحلقة أخرى ومجمع آخر وفق الشروط الأصلية. كل الفحوص على fixtures اصطناعية، دون تسجيل دخول أو بيانات طلاب حقيقيين.

تُختبر القيم الحالية قبل التوصيل، ومراجعها بعده، وبصمات السجلات القديمة التي لم تتغير. يُجرَّب معالِج الورقة داخل API المرشح وحزمة التراجع، وتبقى جميع بوابات #40 والدرجات العلمية #41 فعالة. البوابة الفاشلة تمنع الادعاء بالقبول أو النشر.

## ما يبقى قبل التفعيل

كاتب الإنجاز العام وإلغاؤه وتعديل المشرف ودرجة التحضير والطلبات الدائمة في المتصفح لم تتحول بعد إلى المعاملة الجديدة؛ لا يجوز تشغيل قارئ جديد أمام كاتب غير متوافق. يلي قبول القراءة توصيل الكتابة والدرجة والإلغاء مع هوية التعيين/اليوم/الفصل والعملية نفسها. لا يجوز أن يُستبدل افتقار خلية قديمة للمرجع باختيار خطة الطالب الحالية أو آخر إنجاز بتاريخ متقارب.

يتطلب الإنتاج موافقة محددة على إجراء #36، ونسخًا احتياطية خاصة وفحص استعادة، وترتيب رفع المكتبة قبل المسارات. يلزم تصميم انتقال التبويبات القديمة يحفظ المسودات؛ إذا احتاج توقف التسجيل، يعرض هذا الإجراء المحدد للموافقة قبل التنفيذ. السجلات القديمة تبقى في مخازنها وصفحاتها المعتادة، والعمليات المبهمة وحدها تحتاج مراجعة.

## التراجع

أصبحت حزمة التراجع مبنية على #41 المنشور لكي تبقي حارس الحفظ العلمي المفقود. تبقى قارئات الأحداث ومراجعها وإيصالات الطلبات، دون استعادة قاعدة أو مخزن قديم فوق كتابات جديدة. يجري اختبار معالِج الورقة العام في النسختين على MySQL وMariaDB. الرجوع النهائي لصفحات الدرجة يظل غير معتمد حتى اكتمال توصيل كتابتها؛ أي عطل في الطبقة التي يجب الاحتفاظ بها يستلزم إصلاحًا أماميًا.
