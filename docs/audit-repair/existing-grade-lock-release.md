# قفل مخزن الدرجات الموجود قبل محاولة تهيئته — متابعة F09

فرع مستقل من النسخة المنشورة #41 `ca3d341abc3d63e4c4110cef3c65bb51cf4c3c0e`. ظهر فشل سباق الكاتب القديم على MariaDB في بوابة #45 قبل بلوغ منسق الدرجة والإنجاز الجديد. ملف app_state في #45 مطابق للنسخة المنشورة؛ ليس هذا تراجعًا منشورًا من #45، التي لم تُنشر.

## التغيير المحدود

كان app_state_save_without_reset يبدأ INSERT IGNORE للمفتاح الموجود ثم يطلب FOR UPDATE لقراءته. يُفحص وجود المفتاح بقراءة بلا قفل قبل المعاملة؛ الصف الموجود يدخل مباشرة إلى FOR UPDATE دون إدخال مكرر. الصف الغائب يُنشأ داخل المعاملة، وإذا سبق طلب آخر لتهيئته يُلغى قفل الإدخال المتصادم وتبدأ معاملة قراءة جديدة قبل أي حفظ للدرجة. لا تُعاد كتابة درجة في مرحلة تسوية تصادم التهيئة. تبقى حالة الاستدعاء من معاملة قائمة مرفوضة كما كانت؛ لا يضاف حفظ جزئي داخل معاملة مستدعٍ. تبقى معاملات الحفظ، والتحقق من القيم، ورفض تصفير المخزن غير الفارغ، ومعالجة الفشل، وترميز الطلبات، وجميع شروط الدور والمجمع والمفاتيح حرفية كما في النسخة المنشورة.

لا تغيير في الدرجة أو الحسابات أو محتوى الطلب أو الواجهة أو السجل، ولا مخطط جديد أو إعادة ربط أو إعادة حساب. لا يُدّعى أن هذا وحده يحل استبدال لقطتي درجات كاملتين؛ محرك الخلايا #44 وتوصيله وانتقال العملاء ما زالت مطلوبة لـF09 الكامل. لا تضاف إعادة محاولة تلقائية لكاتب اللقطة القديمة.

## القبول المطلوب قبل الدمج

- SQLite: فخ يرفض تهيئة '{}' لمخزن درجات موجود؛ الحفظ الصحيح ينجح، والصفر والفراغ وnull والعمل الحالي محفوظة. رفض التصفير وفشل الحفظ يحفظان البايتات السابقة. المخزن الغائب فعلًا يبقى قابلًا للتهيئة.
- MySQL وMariaDB: تجربة سلبية بحاجز بين اتصالين تفرض نمط التهيئة المكررة ثم ترقية القفل القديم وتكشف تعارض المحرك دون تعديل أي قيمة. يفرض اختبار آخر غياب المخزن أمام معالجَي حفظ حقيقيين قبل التهيئة؛ ينشئ الأول الصف ويقرأ الثاني نتيجته بعد تسوية تصادم المفتاح، دون إعادة حفظ درجة خارج المعاملة. يبقى اختبار الحفظ الصحيح المتزامن مع التصفير كما هو، ويجب أن يقبل الصحيح ويرفض التصفير.
- حزمة API بديلة تستخدم قراءة مستقلة مكافئة ومعالجة تصادم التهيئة قبل حفظ أي درجة. تعمل اختبارات الحفظ والتراجع عليها في SQLite، وتكتب النسخة المرشحة ثم تقرأ/تكتب البديلة ثم تقرأ المرشحة على المحركين، مع بقاء الحقول الجديدة والقديمة والصفر والفراغ وnull وشكل الكائنات.
- جميع بوابات الواجهة والخادم السابقة والبناء ومقارنة TypeScript مطلوبة. لا تتغير الحزم؛ الاستعادة من cache فقط. لا نجاح مدّعى قبل نتائج CI.

لا يجرب أي مسار على الطلاب الحقيقيين. التحقق المنشور هو SHA وphp-l وملف النسخة وHTML وملفاته الثابتة فقط. تعذر بيئة التحرير المحلية لا يحول الاختبار إلى بيانات حقيقية؛ إعداد الكود عبر GitHub والاختبار على قواعد CI الاصطناعية.

## التراجع وحفظ الأعمال الجديدة

البيانات وصيغتها الأصلية لا تتغير عند النشر. الحزمة ذات API واحد وبصماته محفوظة قبل الدمج؛ لا تستعاد قاعدة أو لقطة درجات قديمة. التراجع الآمن إصدار مقابل من فرع مستقل يطبق مُهيّئ القفل البديل المختبر ويستعمل مسار النشر المعتاد، فيتطابق ملف النسخة مع مصدره في Git. لا تُرفع نسخة API غير مسجلة ثم يُتجاوز فحص البصمة.

إذا تقدم main لاحقًا، يطبّق بديل كتلة التهيئة وحدها على أحدث مصدر، ويُرفض التطبيق إذا تغير سياقها؛ لا يستبدل ملفًا قديمًا كاملًا فيحذف حماية أو بروتوكولًا أضيف بعده. يلزم إعادة اختبار النسخة المقابلة المناسبة قبل نشرها. تبقى الكتابات الجديدة كما هي، ويستعمل إصلاح أمامي عند تعذر هذا الرجوع المحدود.

F01/F02 والدخول والأدوار والرموز وملكية الطلاب وعزل المجمعات خارج التعديل. السجلات القديمة الـ7,737 والدرجات غير المنسوبة تبقى في مصادرها وصفحاتها المعتادة دون مساس.
