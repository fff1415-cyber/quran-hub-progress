## اختبارات القبول

1. 651 سجلًا تصل كاملة إلى التخزين المحلي والطلب والخادم؛ صفر وnull وحقول مجهولة تبقى كما هي. طلب قديم من 500 أو طلب يسقط معرفًا محفوظًا يُرفض بلا تغيير. السجل غير المتوقع يبقى للمراجعة.
2. GET إعدادات في معاملة READ ONLY، وPUT يفشل بعد التهيئة فيتراجع عنها؛ الصفر الصحيح مقبول، ورفض الأدوار الحالية قائم، والمخطط القديم بلا complex_id ما زال يعمل بسلوكه الحالي.
3. استيرادان متزامنان على InnoDB ينتجان تعيينًا واحدًا، واستيراد الخطة نفسها أو المجمدة أو إعادة المحاولة بعد فقد الاستجابة لا يعيد التعيين. واجهة الاستيراد تحتفظ بالمسودة عند فشل البيانات أو الدليل وتعرض سبب رفض الخطة.
4. استجابة قراءة سرد قديمة لا تمحو كتابة محلية انتهت أثناء القراءة. تغيير الجلسة يرفض الاستجابة السابقة؛ الفشل يحفظ العرض الأخير ويتيح إعادة المحاولة. الموعد يصبح مستحقًا والصفحة مفتوحة، وتنظف المؤقتات عند المغادرة.
5. الاختبارات تقارن ملفات الدخول والملكية وعزل المجمعات ومقدمات التحقق وحسابات الدرجات والأوزان والتبعيات ومسار النشر بالأساس. لا تغيير F01/F02.
6. جرد 7,737 صفًا صناعيًا، مع تكرارات وصفر وفراغ، دون حذف أو استنتاج فصل/تعيين. يفشل التحقق عند تبديل المصدر أو إنقاص الجرد.

بوابة `Independent audit release checks` تستخدم PHP/SQLite وMySQL 8 وMariaDB 11.8 المعزولة، وبرامج العميل وأداة الجرد، وبناء `build:hostinger` الفعلي. لا أسرار إنتاج أو خطوة نشر فيها. نتيجة الرأس المحدد في Checks هي دليل الاختبارات؛ نجاح البناء لا يُعتبر نجاح TypeScript الكامل أو اختبار متصفح تفاعلي.

## النشر والتراجع المقترحان — بعد الموافقة

لا SQL جديد أو ترحيل أو إعادة احتساب قديم مطلوب لهذا الإصدار. يرفع API والواجهة متوافقين وفق المسار الحالي مع نسخة واجهة خاصة وفحص المعرف المنشور. يلزم تحديث التبويبات القديمة للاستفادة من إصلاحات العميل؛ الخادم يحمي التاريخ من إسقاط صفوفه حتى من عميل قديم.

بعد بدء حفظ أكثر من 500 سجل، لا يُرجع الخادم إلى الكاتب الذي يقبل الاقتطاع. التراجع المتوافق يُبقي حماية احتفاظ التاريخ ويرجع الواجهة/الأجزاء الأخرى عند الحاجة، أو يستخدم إصلاحًا أماميًا. لا تصفير للسجلات ولا إسقاط للمخازن أو نسخ المراجعة. إرجاع كود الإعدادات لا يعيد قيم إعدادات غيّرها المستخدم بعد النشر؛ هذه بيانات لا يعكسها git revert.

تظل مشكلة تعارض تعديل السجل نفسه F09 ومعاملة الاجتياز F08 منفصلتين. هذا الإصدار يجعل فشل مزامنة التاريخ ظاهرًا ويحفظ سجلات الخادم من الإغفال؛ لا يدعي جعل الاجتياز والسجل الأكاديمي معاملة واحدة قبل مرحلة F08.
