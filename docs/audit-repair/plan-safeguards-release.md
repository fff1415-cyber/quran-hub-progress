# التعيين المحدد ومقطع البداية — F07 وبقية F20

## التغيير والقبول

- التجميد والاستئناف يستهدفان assignment_id المعروض، تحت قفل صف الطالب ومعاملة. إعادة تجميد التعيين نفسه لا تعيد كتابة تاريخ تجميده. الهدف القديم أو المفقود يعطي خطأ واضحًا؛ لا يُستنتج هدف من آخر طالب/خطة.
- الربط اليدوي يحمل التعيين الذي عُرض للمستخدم. إعادة الطلب القديم أو استجابة شاشة سابقة لا تستبدل التعيين الجديد. استبدال خطة مجمدة ينقل تعيينها إلى التاريخ ثم ينشئ الحالي في المعاملة نفسها.
- كل مساري تفعيل التعيين في التطبيق يقفلان صف الطالب نفسه. التعيينات الحالية المتعددة القديمة لا تُحذف أو تُصلح تلقائيًا؛ ترفض العملية المتعلقة بها وحدها للمراجعة. القيد الفريد على مستوى قاعدة البيانات مؤجل إلى خطة الترحيل المعتمدة، ولا يُدعى ضمان ضد كتابة SQL خارج التطبيق.
- البداية يجب أن تكون عددًا صحيحًا موجبًا ومقطعًا موجودًا فعلًا، بما فيه خطة ذات مقاطع متقطعة. لا يُحوَّل الصفر أو الكسر إلى 1. تُرفض البداية غير الموجودة قبل إغلاق الخطة الحالية.
- اللوحة تنتظر تحميل التعيين، وتتجاهل استجابة الطالب السابق، وتمنع تكرار النقر أثناء الحفظ، وتعرض الخطأ وتعيد تحميل الهوية قبل إعادة المحاولة. معيار المسمّع والاجتياز والمحاولات لم يتغير؛ المسمّع لا يرحّل تعيينًا مجمدًا كما كان سابقًا.

الملفات: `api/routes/plans.php`، `src/lib/plans-service.ts`، `src/components/plans/SupervisorPlansPanel.tsx`، واختبارات القبول وحراسة النطاق ووسائل فحص النشر. لا تعديل لملفات الدخول أو الأدوار أو الطلاب/الملكية أو عزل المجمعات أو قواعد الحساب، ولا مخطط أو حزم جديدة.

## التحقق المعزول

`assignment-target-regression.cjs` و`assignment-panel-regression.cjs` يستدعيان خدمة الخطة وأزرار المشرف الفعلية. `backend-plan-safeguards.php` يستدعي المعالجات الحقيقية على SQLite. حالات MySQL/MariaDB في `backend-independent-mysql.php` تشمل تنافس الاستئناف والاستبدال، التكرار، فشل CHECK والتراجع، مقطع منتصف صحيح ومقطع مفقود، وتعيينات ملتبسة محفوظة. تُعاد اختبارات #25 والميزات التابعة معها.

لا اختبار متصفح كامل بحسابات فعلية. فحص TypeScript الكامل يبقى منفصلًا عن نجاح البناء؛ أخطاؤه الأساسية لا تُصلح عبر تعديل النطاق المستبعد.

## النشر والتراجع

لا ترحيل أو تسوية أو إعادة احتساب. يُرفع ملف API المتغير الوحيد `routes/plans.php` بعد فحص بصمة الأساس ونسخة كود خاصة واختبار استخراجها، ثم فحص PHP وبصمته ثم الواجهة. تفحص الخطوة الأخيرة معرف الإصدار وHTML وملفات JavaScript/CSS فقط؛ لا تنفذ JavaScript أو API.

التنسيق المخزن لم يتغير؛ تبقى جميع التعيينات والإنجازات القديمة والجديدة مقروءة. نسخة تراجع الواجهة وAPI تحفظ خارج مجلد الموقع. لا يستعاد DB أقدم فوق كتابات جديدة. التراجع الانتقائي المفضل يبقي حماية التاريخ من #25 وحراسة التعيين على الخادم؛ واجهة قديمة لا ترسل معرّف التعيين ستتلقى طلب تحديث بدل تعديل تعيين آخر. التراجع الكامل للكود يعيد عيوب استهداف التعيين القديمة، ولذلك يحتاج خطة إصلاح أمامي عاجل ومراجعة أثره، ولا يُجرى تلقائيًا بمجرد فشل تحقق شكلي.
