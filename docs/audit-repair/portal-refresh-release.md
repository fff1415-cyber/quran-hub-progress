# قراءة الدرجات المشتركة وتأكيد إجراء المدير — الجزء المستقل من F17

الأساس المنشور `9d843a4aac7282392ee4ee661c4f589488cbda49`؛ الفرع `fix/audit-safe-portal-refresh`.

## النطاق

- صفحة الطالب/ولي الأمر، ونتائج الحلقات وتتبع الحفظ للمشرف، ونظرة المدير: تقرأ مخزن الدرجات المشترك الحالي كل عشر ثوانٍ عند ظهور الصفحة، وعند العودة إليها. تدمج القراءات المتزامنة، وتتجاهل رد الجلسة/المجمع السابق، وتحتفظ بالعرض السابق مع سبب الفشل وإعادة المحاولة. الصفر والفراغ والحقول غير المعروفة لا يعاد تفسيرها أو حفظها.
- الاستطلاع الجديد يستدعي فقط GET للمفتاح `grades`، ولا يكتب في التخزين المحلي أو المشترك، ولا يستدعي الطالب/الخطة/تقارير الاعتماد أو التقويم دوريًا. بعض مسارات القراءة القديمة لها آثار جانبية؛ لم تضف هذه الدفعة استطلاعًا لها. التحميل الأولي القائم يبقى كما هو.
- يضيف GET الدرجات سياق التقويم المقروء حاليًا باستعلام SELECT خالص، وفق شرط المجمع الموجود نفسه. عند تغير الفصل عن فترة الشاشة لا يطبّق الرد ويطلب إعادة فتح الصفحة. تعدد الفصول النشطة لا يعالج بالتخمين. **السياق يصف الطلب الحالي، ولا يثبت فصل السجلات القديمة**، ولا يصلح F10 أو يصنّف المخزن الأصلي.
- إجراء المدير «الإعادة الآن» ينتظر تأكيد قائمة السرد قبل النجاح والإشعار المحلي، ويمنع النقر المتكرر ويعرض الفشل. الصلاحيات والتوجيه والمحاولة والمعيار والموعد يبقون كما كانوا.

لا تعديل للمصادقة/الأدوار/الملكية/عزل المجمعات، ولا مخطط جديد أو تغيير لصيغ البيانات والدرجات والحسابات والفترات. `secureListAppState` يضيف `cache: no-store` لطلب البيانات فقط؛ منطق الدخول والترويسات والصلاحيات لم يتغير.

## القبول وحدوده

اختبارات callbacks الفعلية مع نقل معزول: لوحتان بطلب واحد؛ صفر ونص صفر وnull؛ لا كتابة أو إشارة جانبية؛ فشل وإعادة محاولة؛ فصل أو جلسة قديمة؛ تبويب مخفي؛ إلغاء المكون؛ إجراء المدير لا يعلن نجاحًا/إشعارًا قبل ACK ويقبل إعادة المحاولة بعد الفشل. حراسة مصدر صفحة الطالب تقارن منطق الدخول والطالب والزيارة والحسابات حرفيًا مع الأساس. يعاد تشغيل بقية اختبارات الميزات.

SQLite وMySQL 8 وMariaDB 11.8: تشغيل GET الحقيقي داخل وضع/معاملة READ ONLY، مع مخزن درجات قائم وفارغ، وفصل مفقود أو متعدد ومجمع آخر؛ مقارنة السجلات الخام وعدم إنشاء صفوف أو جداول. اختبارات التزامن والخطط والإعدادات السابقة تعاد أيضًا. لا حسابات طلاب حقيقية أو إشعارات تجريبية. لا اختبار متصفح كامل بين أجهزة حقيقية؛ هذه اختبارات واجهة ودوال وطلبات معزولة، والتحقق المنشور ثابت فقط.

صفحة تقرير الأوجه وتقارير الاعتماد تبقى بتحديثها اليدوي، لأن ربطها باستطلاع الدرجات قد يستدعي مسارات قراءة ذات أثر جانبي. تزامن كتابة الدرجات F09/F11 وفصلها F10 في مسودة مستقلة؛ لا تنشرها هذه الدفعة.

## النشر والتراجع

الـAPI أولًا، ملف `api/routes/app_state.php` فقط مع فحص بصمة الأساس ونسخة خاصة واختبار استخراج/مطابقة وفحص PHP، ثم الواجهة. الإضافة في استجابة GET متوافقة مع الواجهة السابقة. تحقق المنشور يقرأ معرف النسخة وHTML وملفات الدخول الثابتة فقط، دون تنفيذ التطبيق أو API.

`prepare-portal-refresh-rollback.py` يبني واجهة الأساس 9d843a4 ويختبر بقاء قارئ قواعد المراجعة المثبتة، ويجهز نسخة ملف API السابق ويختبر استخراجها حرفيًا. يحفظ CI الحزمة وبصماتها لمدة 30 يومًا، ويمكن إعادة بنائها من نفس النسخة. التراجع يعيد هذين الجزأين فقط؛ لا يعيد قاعدة بيانات قديمة أو مخزن درجات ولا يمس الكتابات التي جرت بعد النشر. لا صيغة تخزين جديدة في هذه الدفعة. لا يستخدم أساسًا أقدم يتجاهل قواعد المراجعة أو يعيد اقتطاع السجل.
