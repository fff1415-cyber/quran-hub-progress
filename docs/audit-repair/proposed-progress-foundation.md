# إجراء قاعدة مقترح: جداول جديدة فارغة فقط

**غير منفذ على الإنتاج وغير مفعّل في التطبيق.** يراجع هذا الإجراء مستقلًا عن نشر #33–#35، ولا يعد موافقة النشر المستمرة إذنًا لتشغيله.

## الإجراء المحدد المطلوب اعتماده

تشغيل `database/proposed-progress-foundation.sql` بعد نسخة قاعدة خاصة مثبتة الاستعادة وفحص عدم تعارض الأسماء. ينشئ ثمانية جداول فارغة فقط:

| المجموعة | الجداول | الغرض المستقبلي |
|---|---|---|
| إصدارات المحتوى | plan_content_versions، plan_catalog_versions، plan_assignment_versions | محتوى ثابت ومؤشر دليل ومرجع تعيين صريح، دون تغيير معرفات الخطة الحالية |
| العمليات والإنجاز | plan_operation_receipts، plan_completion_events، plan_completion_heads | إيصال طلب، حدث إنجاز/عكسه، ومؤشر الحالة للتعيين المحدد |
| تزامن الخلايا | grade_cell_versions، grade_operation_receipts | إصدارات مسارات وإيصالات مستقلة، مع بقاء الدرجات الأصلية في app_state |

لا يحتوي الملف ALTER أو INSERT أو UPDATE أو DELETE أو DROP. لا يضيف فهرسًا إلى الطلاب أو التعيينات القديمة، ولا يغير مجمعًا أو ملكية أو صلاحية. الروابط المرجعية الجديدة بين الجداول الجديدة فقط وبسياسة RESTRICT؛ لا سلسلة حذف تصل إلى المصادر الحالية.

لا ينقل أيًا من الإنجازات الـ7,737 المرصودة في فحص 2026-10-28، ولا ينسخ درجات أو ينسبها إلى فصل، ولا يلتقط محتوى لتعيين قديم تلقائيًا. العدد ليس جردًا محدثًا للإنتاج. تبقى كل السجلات في مكانها وفي الصفحات المعتادة؛ التوجيه السابق إلى أرشيف منفصل ملغى وفق تعليمات المحافظة على العمل الجاري.

هذا تمهيد لمراحل F04/F05/F06/F19 وتزامن F09/F11؛ لا يعني أن واجهاتها أو معاملات الحفظ المستقبلية اكتملت. تفعيل كاتب جديد يحتاج دفعة كود مختبرة وقارئ/كاتب تراجع متوافقين. لا يُرفض الكاتب القديم ولا تتوقف عملية التسجيل بمجرد إنشاء هذه الجداول.

## قبل الإجراء

1. تحديد نسخة SQL وبصمتها من الالتزام المختبر. مراجعة SHOW TABLES وSHOW CREATE TABLE للقراءة فقط. **إذا وجد أي اسم من الأسماء الثمانية مسبقًا، يتوقف الإجراء المحدد هنا** حتى مطابقة تعريفه ومعرفة مصدره؛ IF NOT EXISTS لا يثبت توافقه.
2. نسخة خاصة متسقة لقاعدة الإنتاج ومخططها خارج مجلد الموقع، مشفرة وبصلاحيات التخزين الحالية، مع SHA-256 ووقت القطع وأعداد الصفوف. تجربة استعادة نسخة فعلية على MariaDB معزول والتحقق من القيم الخام والروابط؛ نسخة ملفات الموقع لا تغني عنها. لم يجر ذلك على نسخة إنتاج ضمن هذه الدفعة.
3. لا تغيير لمستخدم القاعدة أو منح صلاحيات جديدة. إذا لم تكفِ القدرة الحالية، يعود ذلك كعائق منفصل ولا يوسع هذا الإجراء النطاق.
4. تقدير موارد الاستضافة وفترة تنفيذ DDL. الجداول الجديدة لا تشير إلى الجداول القديمة، لذلك لا يتوقع توقف تسجيل للمرحلة الفارغة. إذا تبين أن الاستضافة تتطلب توقفًا، يعرض الإجراء المعدّل للموافقة أولًا.

## التنفيذ بعد الموافقة فقط

- ينفذ المسؤول المخول ملف SQL المحدد مرة واحدة. لا يشغله API أو GET أو مسار النشر.
- التحقق بالقراءة: الجداول الثمانية موجودة وفارغة وInnoDB، وتعريفاتها ومفاتيحها متطابقة مع الملف المختبر. لا تتغير تعريفات الجداول القديمة.
- لا تقارن أعداد الطلاب الحية على أنها ثابتة إذا استمر التسجيل؛ تحقق من غياب أي عبارة تعديل للمصادر القديمة، ومن سلامة النسخة والقراءة المعتادة. لا تعزل كتابات الطلاب الجارية أو تعيدها إلى وقت النسخة.
- DDL في MySQL/MariaDB ليس معاملة قابلة للتراجع. عند انقطاعه تحفظ الجداول المنشأة، وتجرد تعريفاتها. لا تعاد المحاولة عمياء على جدول مختلف. اختبرت إعادة ملف مطابق بعد انقطاع مصطنع، لا توافق جدول مجهول.

## التراجع وحدوده

قبل التفعيل: لا يرجع أي صف إنتاج إلى الماضي؛ تبقى الجداول الجديدة الفارغة دون استخدام ويستمر الكود الحالي. لا حاجة إلى DROP أو استعادة قاعدة. بعد بدء كتابات مستقبلية: لا تحذف الجداول ولا تعيد نسخة قديمة فوقها؛ يلزم كود متوافق يحفظ الأحداث وإيصالاتها أو إصلاح أمامي. هذا الإجراء وحده لا يعتمد خطة تفعيل أو توقف الكاتب القديم.

## التجربة المعزولة

CI يشغل المعالجات الحالية واختباراتهم أولًا على MySQL 8 وMariaDB 11.8، ثم ينشئ 7,737 إنجازًا اصطناعيًا بربط مجهول/غير مطابق و12 مخزن درجات دون فصل (6+2+4)، مع الصفر والفراغ وnull وحقول إضافية.

تؤخذ بصمات تعريفات وقيم كل الجداول الحالية قبل وبعد SQL، ويجرب الانقطاع بعد أول CREATE وإعادة الملف مرتين. يجب أن تبقى الجداول الجديدة فارغة والمصادر القديمة مطابقة. تختبر قيود نسخة المحتوى والحدث/عكسه وهوية الإيصال بأمثلة مستقبلية معزولة، ثم استعادة أصلية في خدمة قاعدة ثانية قبل وبعد المخطط. تتحقق قيود FK بعد الاستعادة وتطابق الصفوف والتعريفات. هذه اختبارات مخطط وقيود، وليست ادعاء اختبار الرحلات المستقبلية أو استعادة بيانات إنتاج مفقودة.

## القديم: ما يحتاج قرارًا لاحقًا

- الموافقة الحالية على إبقاء العمل ظاهرًا في موضعه محسومة؛ لا نطلب قرار أرشفة جديدًا.
- يلزم مصدر إثبات حقيقي وقرار محدد قبل نسخ إنجاز مجهول إلى تعيين، أو نسبة خلية درجة إلى فصل. تحفظ المصادر والبصمات الأصلية، ولا يستبدل هدف له كتابة أحدث.
- المحتوى الذي استبدل سابقًا لا يستعاد من الدليل الحالي. اللقطة المستقبلية الموسومة observed_current تعني ما شوهد في تاريخها فقط؛ استعمالها لأي تعيين قديم يحتاج الإجراء المعتمد الخاص به.
- معيار أيام العمل والإجازات F12، وأثر إعدادات التقييم على المستقبل F16/المراجعات القديمة، تبقى قرارات عمل منفصلة.
- تزامن الخلايا يجهز على المخزن الأصلي، دون أرشفة. إذا احتاج قطع الكاتب القديم إلى توقف أو تحديث منسق للتبويبات، تعرض خطة محددة ونتائجها قبل الإجراء؛ لا يفعل ذلك هذا الملف.

ملاحظة تحقق MySQL: أثبتت المقارنة أن القيم وأعداد الصفوف مطابقة، بينما أضاف SHOW CREATE بعد الاستعادة عبارة CHARACTER SET utf8mb4 الزائدة قبل COLLATE utf8mb4_unicode_ci. يقارن الاختبار تعريفات الأعمدة الفعلية بما فيها الترميز والتجميع، وكل رموز DDL عدا هذه العبارة الزائدة المحددة. تبقى بصمة DDL الخام مطلوبة دون تطبيع لإثبات عدم تعديل الجداول الأصلية أثناء الترحيل، وتبقى مقارنة بيانات الصفوف حرفية. لا يتجاهل الاختبار تغيير نوع أو قيد أو collation.

بعد إنشاء الجداول الفارغة يشغّل الاختبار معالج استمارة الطالب الحالي وقراءة الدرجات داخل معاملات READ ONLY، ويتحقق من بقاء الخطة الحالية ظاهرة ومن تطابق كل المصادر القديمة. يتضمن ضابطًا سلبيًا يغيّر collation حقيقيًا في قاعدة الاستعادة الاصطناعية؛ يجب كشف اختلافه ثم تعاد الاستعادة الأصلية، حتى لا يخفي تطبيع SHOW CREATE فرقًا فعليًا.
