# مرجع المراجعة المؤجلة وتأكيد الإجراءات وحفظ السجل المحلي

الأساس المنشور `bfe3ef13d0451aa55584c28515d4249486298ff3`؛ الفرع `fix/audit-safe-score-records`. هذه الدفعة لا تغير مخطط قاعدة البيانات أو صيغة مخازن الدرجات أو قواعد الاجتياز/التقريب/عدد المحاولات أو أي صلاحية.

## النطاق

- **F15 — الجديد المؤكد فقط:** عند تثبيت الحفظ وجدولة مراجعة مؤجلة جديدة، يحفظ الطلب نسخة القواعد المستخدمة فعلًا ومرجعها وتاريخها. إعادة جدولة/إعادة المراجعة تستخدم النسخة نفسها حتى لو تغيرت إعدادات المجمع. سجلات المحاولات الجديدة التي تُكتب تحمل مرجع القواعد المستخدمة. لا تنسب أي قواعد للمراجعة القديمة بلا مرجع، ولا يعاد حساب سجل محفوظ. المراجعة القديمة تبقى بسلوكها الحالي مع تنبيه صريح؛ تصحيح قواعدها القديمة يحتاج مصدر إثبات/قرار مستقل.
- **F17 — إجراءات المسمّع:** جميع فروع الرسوب وجدولة الإعادة/المراجعة تنتظر تأكيد حفظ قائمة السرد قبل إعلان النتيجة أو إنشاء الإشعار المحلي أو إغلاق الاستمارة. يظهر الحفظ الجاري وسبب الفشل؛ يمنع النقر المكرر وتتاح إعادة المحاولة. معرّف سجل رسوب الحفظ مستقر للمحاولة نفسها لمنع تكرار السجل عند إعادة الطلب.
- **F03/F14 — حفظ المحلي المستقل:** يظل صندوق التحويل محليًا وفق النطاق الحالي، لكن الحفظ والدمج والإضافة لا تقتطع السجلات عند 200. تحفظ نسخة خام من المخزن القديم قبل أول كتابة. وظيفة الحذف الصريح الحالية تبقى؛ لم تتغير الأدوار أو التوجيه أو نطاق المستلمين، ولا ادعاء بتفعيل التوصيل بين الأجهزة.

الملفات التطبيقية: `evaluation-types.ts`, `evaluation-rules-snapshot.ts`, `sard-phased-flow.ts`, `mock-data.ts`, `routes/musammi.tsx`. لا ملف API متغير أو تغيير حزم. لا إشعار أو عملية طالب حقيقية ضمن التحقق.

## الاختبارات والحدود

اختبارات callbacks الفعلية لكل محاولة رسوب وللمراجعة المؤجلة وللرسوب النهائي: لا إشعار/إغلاق قبل التأكيد، فشل ثم إعادة محاولة، نسخ قواعد مستقلة عن كائن الإعدادات، وقواعد مراجعة مثبتة بعد تغيير إعدادات الحساب. اختبار PHP حقيقي يحفظ المرجع ثم يقرأه في وضع read-only، ويحقن فشلًا يتحقق من بقاء القواعد والموعد السابقين. اختبر 651 إشعارًا محليًا وأفعال تحويلها دون اقتطاع. يعاد تشغيل حراسة الصلاحيات والميزات السابقة وMySQL/MariaDB والبناء.

هذه ليست معاملة موحدة للاجتياز والخطة والسجل الأكاديمي (F08)، ولا تحل CAS مخازن الدرجات (F09/F11) أو الفصل بينها (F10). فشل مزامنة التاريخ ظاهر منذ #25، لكنه لا يجعلها معاملة واحدة مع قائمة السرد. لا اختبار متصفح كامل بحسابات حقيقية، ولا استعادة لصفوف اقتطعت سابقًا دون مصدر.

## النشر والتراجع

رفع واجهة فقط بعد نسخة خاصة واختبار استخراجها. تحقق المعرف وHTML وملفات الدخول الثابتة دون API. تبقى البيانات بصيغتها الحالية مع حقول اختيارية على السجلات الجديدة؛ لا يسوي التراجع أي سجل. يلزم الاحتفاظ بدعم قراءة القواعد المثبتة إذا بدأت مراجعات جديدة تحملها؛ الرجوع إلى قارئ قديم يتجاهل المرجع يعيد خطر القواعد المتغيرة. وسيلة التراجع المتوافقة هي الاحتفاظ بقارئ المرجع والمصدر المؤكد، والتراجع الانتقائي عن جزء الواجهة المتعثر أو إصلاحه أماميًا، مع بقاء حماية التاريخ والخادم من #25/#27. نسخ الكود الخاصة لا تستخدم لاستعادة قاعدة أقدم فوق كتابات أحدث.

تُجهز حزمة تراجع فعلية قبل النشر بواسطة `prepare-record-confirmation-rollback.py`: تبني واجهة الأساس مع الإبقاء على قارئ/كاتب مرجع المراجعة وحماية التاريخ الكامل، وتختبر قارئها على مرجع من الإصدار الجديد ثم تشغّل build:hostinger. تُحفظ الحزمة الخاصة في أثر CI باسم `record-confirmation-compatible-rollback` لمدة 30 يومًا؛ يمكن إعادة بنائها من نفس الرأس بعد ذلك. لا يرفع اختبار الحزمة أي ملف ولا يستدعي خدمة إنتاج. لا تُستخدم حزمة الواجهة الأقدم مباشرة إذا كانت ستتجاهل المرجع أو تعيد اقتطاع السجل.
