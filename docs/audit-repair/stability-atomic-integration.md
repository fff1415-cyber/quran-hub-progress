## Daily save behavior

The teacher/assistant grade writer records immutable per-operation packets in account/complex-scoped browser storage before announcing a local edit. Independent operation keys avoid one tab replacing another tab's queue. A matching server receipt is required for confirmation. Response loss retries the same packet/ID; later edits use dependency IDs and exact cell revisions rather than device clocks. Conflicts retain the draft and show saved/draft values for an explicit comparison. Reopening preserves pending operations. Known semester changes fence stale writes; unknown historical semesters are not invented or moved.

The API retains existing authorization guards. An explicit QHP_GRADE_WRITES_V1=true rollout flag is required; it is OFF by default and has not been set on production. When enabled, legacy whole-grade replacement and standalone legacy plan apply/undo are refused. The staged #44 data engine is reused with explicit callback identity in receipts. No request-time DDL is added. Two new version/receipt table definitions are tested only in isolated fixtures. A compatible rollback must retain this protocol and legacy-writer fence after activation, never restore an old database over newer writes.

Planned daily hifz/rabt/muraja and compensation use one grade packet with the observed assignment ID and selected calendar date. Grade, completion, link metadata, immutable plan event and receipt commit together. The server validates the selected week/day/date against the existing calendar and holidays. Compensation derives the current weekly total under the same lock, keeps the existing gold floor/silver half-face conversion and five-face cap, and retains event copies when decreasing known rows. A changed/frozen/ambiguous assignment rolls back the grade too. Known reversals preserve the complete creation/reversal events and original row payloads; only their newly tracked active projection is removed. Unknown legacy completions/compensation links remain byte-for-byte untouched and cannot be undone by guessing. Existing historical null-assignment rows are not rebound. Internal plan event keys cannot be read or replaced through generic app-state routes; this introduces no new role permission. Kiosk attendance uses a targeted versioned write, preserving its existing attendance policy and neighbouring teacher cells.

These tests are not a full browser E2E run with production accounts.

Release is still held for verified restoration, actual main/m2 vhost isolation, current production backup restore proof, full UI/browser acceptance and a tested compatible rollback package.
