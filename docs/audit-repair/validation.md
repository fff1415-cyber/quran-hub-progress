# تسليم إصلاحات F03–F22

الأساس: `7e9adf1d4059f20289f182e31613e18fe2cf0877`، وهو `main` عند البدء وعند التحقق الختامي. الفرع: `fix/audit-f03-f22-preserve-history`. طلب الدمج مسودة #22. لم يحدث دمج أو نشر أو اتصال تجريبي بالموقع الفعلي أو تعديل لبيانات الإنتاج.

## النطاق المحمي

F01 وF02 مستبعدان. اختبار `scope-guard-regression.cjs` يقارن ملفات الدخول والصلاحيات وملكية الطلاب وعزل المجمعات بالأساس حرفيًا، ويقارن مقدمات التحقق في المسارات التي عُدلت، وملفي الحزم والقفل. لم تُمنح أدوار جديدة ولم تُغيَّر رموز الدخول أو مرشحات وصول الحسابات. بيانات هوية صندوق إعادة المحاولة محلية لتنظيم الطلبات وليست مصدر تفويض؛ الخادم يستعمل التحقق الأصلي.

هذا لا يعني إصلاح مخاطر F01/F02. خصوصًا لا يمكن ضمان خصوصية مستلم التحويل عبر `/app-state` الحالي؛ لذلك لا ينشر هذا الفرع إشعارات التحويل فيه ولا يسحبها منه. العمل المحلي للتحويلات بقي متاحًا، مع حفظ سجلاته وتوضيح حدوده في الرسائل.

## ما اختُبر فعلًا

- استدعاء الدوال الخلفية الحقيقية على SQLite ببيانات صناعية؛ محول SQLite يزيل أقفال MySQL ولا يُعد دليلًا عليها.
- MySQL 8 في خدمة مؤقتة باسم اختبار ثابت وعلى loopback، مع رفض أي DSN آخر ودون استيراد إعدادات الإنتاج. نُفذت الترحيلات مرتين، والتكرار المتزامن، وطلبان مستقلان، وقيد التعيين الحالي، ومعاملات يومية متزامنة وحقن فشل بقيد CHECK. لم تُمنح صلاحيات إضافية.
- إعادة الخطة نفسها، بدء من المنتصف وبداية غير موجودة، تجميد ثم استبدال ثم استئناف قديم، إلغاء قديم بعد تعيين جديد، واستيراد دليل فعلي يحفظ محتوى السابق ويعطي الجديد النسخة المستوردة.
- درجة/إنجاز/سجل في معاملة واحدة، وفشل إدخال أو حفظ درجة أو ملف مرحلة أو قائمة أو سجل أكاديمي، وفقد استجابة وإعادة الطلب. سياسة الاجتياز القائمة واختبار الحفظ وحده بقيتا.
- التعويض الذهبي بنصفين مؤرخين، عكس نصف سابق، وتحرير تعويض تعيين سابق دون المساس بالجديد. التحويل الحالي محفوظ: الذهبي floor لمجموع الأسبوع، والفضي round للأوجه ×2، دون اختراع تاريخ للتعويض القديم.
- فصلان بأسبوع 1، تبويب قديم، قراءة فصل سابق وقراءة القديم غير المنسوب، تعارض خلية، خلايا مختلفة، تبويبان على صندوق طلبات واحد، مسح صريح، صفر ومفقود، و651 سجلًا.
- حدود الأدوار القائمة: رفض الربط غير المخول، قبول المعلم المشروع، رفض حلقة مختلفة، وقراءة الطالب وولي الأمر للإنجاز نفسه في بيانات الاختبار. هذا اختبار عدم تراجع، وليس إصلاح F01/F02 أو إثبات أمان جميع المسارات.
- اختبارات واجهة ودوال نقل معزولة: كمية الحفظ الفعلية، جميع قيم pass/fail/clear، نبض موعد أثناء بقاء الصفحة، عدم النجاح عند فشل الحفظ، وعزل استجابة إعدادات الجلسة السابقة.
- بناء Vite للعميل وSSR باستخدام `npm run build:dev` في نسخة مؤقتة، دون تشغيل الموقع أو سكربت نشر. ملفات الحزم والقفل لم تتغير.

فحص TypeScript الكامل ليس أخضر: في الأساس 35 تشخيصًا، وفي الإصلاح 31 عند المقارنة مع نسخة الأساس بنفس الاعتماديات، دون تشخيصات جديدة. الباقي يشمل تكامل Supabase ومناطق التربوي وأنواع توجيه/تصدير قديمة. لا يُسوّى فشل الفحص الكامل بنجاح البناء، ولم تُعدّل ملفات الدخول لمعالجة أخطاء أنواعها.

## حدود التحقق والقرارات

لم يُنفَّذ اختبار متصفح تفاعلي كامل بجهازين أو بحسابات حقيقية، ولا اختبارات دفع/إشعارات فعلية، ولا ترحيل على نسخة بيانات إنتاج، ولا قياس حمل بحجم الإنتاج. التغطية بين الحسابات هي دوال خادم حقيقية ووسائط نقل وواجهة معزولة؛ تأكيد رحلة المتصفح الكاملة يحتاج بيئة تجريبية وحسابات صناعية.

1. **F03/F17:** يلزم مسار مشترك يطبق نطاق المستلمين، أو تفويض صريح لاحق لمعالجة هذا النطاق. لا يُستعمل المخزن العام لتمرير بيانات التحويل.
2. **F12:** هل المقام أيام العمل المقررة بعد الإجازات أم الأيام المنقضية؟ وكيف يعامل الأسبوع الجزئي والتعويض؟ المعاينة لا تغيّر النسب الفعلية.
3. **F16:** اعتماد معنى نقاط الحفظ (خانة إنجاز كاملة مقابل نقاط الكمية)، والإعفاء/الغياب، وتاريخ التطبيق المستقبلي، ومعالجة المقامات والمسار عند تعديل سجل قديم. المسودة لا تنشط هذه القواعد تلقائيًا.
4. **F15:** توفير مصدر لقواعد المحاولات القديمة المثبتة، أو اعتماد إجراء يدوي منفصل. لا يمكن استعادة قواعد لم تُحفظ من القيم الحالية بالتخمين.
5. **القديم الملتبس:** إثبات الفصل أو التعيين من مصدر حقيقي قبل أي تسوية. لا تُستنتج الهوية من آخر تعيين أو عنوان الخطة أو تاريخ تحديث صف عام.

التفاصيل التشغيلية وحدود الرجوع في [deployment.md](deployment.md). جميع الأجزاء المعلّقة مستقلة ومعلّمة؛ لا يوجد نشر أو ترحيل ضمن هذا التسليم.
