# Failed/deferred assessment confirmation

Application dependency: #60, after #59 and the earlier stack. Draft-only; no merge, deployment, production write or runtime migration. The actual independent restore/current backup/domain-isolation gates remain required.

Full and review-only evaluator failure/deferral callbacks submit raw errors/warnings, original adopted rules and queue change as one immutable operation. The complete packet is persisted in an account/tenant-scoped outbox before flushing older queue writes or contacting the network. No local next-attempt update, notification or success is performed before confirmation. Reopening the app retries the original packet; a changed assessment is not substituted. Quota failure prevents a new send, uncertain results remain visible, and explicit conflicts require review. Late tab failures cannot downgrade a verified result.

The existing app-state authorization remains in force; no role grant is changed. A read-only `/sard/capabilities` endpoint in the same PHP file as the queue writer is mandatory before sending protocol 1. An old backend cannot receive the new packet merely because the client can reach the old generic queue API.

Under the existing queue row lock, the server checks CAS, source assignment and existing attempt readiness/deadline. It binds immutable history identity, student, assignment, queue, week, attempt and timestamp server-side. Queue outcome, all detailed assessment data and the internal receipt commit together. The receipt is actor/input/tenant-bound and uses a private `grade_` namespace blocked from generic reads/writes. Matching retry returns the original receipt before applying current-state checks, preserving newer supervisor decisions. Current queue is read after confirmation; stale receipt snapshots are never written into it.

Metadata guards refuse writes when `app_state` is not InnoDB or lacks the exact unique tenant/key index. Protocol-2 passing transitions also require transactional student/profile and assignment tables. These checks perform no DDL; native tests substitute disposable bad-engine/bad-key tables and prove refusal before writes.

Every former history row remains; no truncation, relabeling or historical attribution by guess. Newly recorded deferred review attempts are distinct immutable assessment events, preserving their raw counters even when the next retry resets the visible inputs. Existing thresholds, delay calculation, first/second/third-attempt routing and locked-hifz policy remain unchanged. Legacy manual queue actions still use their established CAS path. Legacy local musammi transfer notifications remain local under the separately approved shared-transfer exclusions; there is no guessed migration into the new transfer policy.

Synthetic acceptance includes the actual UI callbacks, actual serializer and production router across independent sessions, offline-before-first-request/reopen/lost-reply recovery, same-item conflict, current supervisor decision retention, quota/account isolation, 651-row history retention and late SQL rollback. MySQL 8 and MariaDB 11.8 additionally test independent concurrent receipt recovery. The old backend regression fixture now asserts private failure references and refusal of request-time schema migration, matching the previously shipped safety changes. These tests do not prove real Hostinger restore or account/browser acceptance.
