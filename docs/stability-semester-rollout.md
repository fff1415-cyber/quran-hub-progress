# Semester and academic write candidate

Base: PR #56, which retains #50 → #51 → #52 → #53 → #54 → #55. PR #57 is an independent read-only hosting access probe and is not required for application behavior.

This candidate is **not a production release**. Do not merge to a deployment branch or activate flags until the independently authenticated test database restore, current production backup, real vhost/domain isolation, and acceptance requirements are evidenced. Existing pipeline path restrictions are not proof of m2 isolation.

## Behavior

- Scientific edits use immutable, account-scoped outbox packets. A manual score and its override are one atomic request. Rejected/uncertain requests remain drafts, with explicit conflict review. No whole-store scientific merge upload remains in the main sync path.
- Weekly results use the existing authorized result endpoint. Independent slot writes merge, same-slot conflicts are explicit, and attribution is generated by the authenticated server in the receipt transaction. Committee and teacher/assistant halaqa guards are retained.
- Daily, scientific and weekly stores can use physical keys `term:<semester-id>:<logical-key>`. Versions, receipts and grade/plan cell projections use the same scoped key. An old-period packet cannot write into a new semester. Known receipt replays are read-only acknowledgements.
- The original unscoped blobs are never copied into a guessed semester, replaced or deleted. History is explicitly read-only; the UI separates the unknown-period history and known stored semesters. Pagination affects display only, never stored records.
- The current semester's initially missing scientific store inherits legacy configuration only, with empty score/override sections. Configuration edits are scoped to the selected semester; a later semester starts from the preserved legacy configuration unless explicitly configured. There is no automatic carry-forward of scores or overrides.
- Daily UI mutations carry the displayed semester. Scientific autosync requires confirmed prep and matching prep/scientific/displayed calendars. A background snapshot refresh cannot silently rebase a stale screen into a new term.
- Passing a nonfinal plan with an academic packet commits the previous assignment closure, new assignment, profile, queue result, academic record and immutable transition receipt together. Receipt replay cannot create another assignment or overwrite a previous academic record. Generic historical writes cannot replace the confirmed transition record.
- Academic records use per-account local caches; the former unscoped browser cache remains untouched. Read-only refresh preserves local rows and prefers server values for matching IDs. Confirmed transitions produce deterministic local teacher notifications on each device after its read; repeated refresh preserves the notification's read state. No external message dispatch was added.

## Explicit rollout switches

`QHP_GRADE_WRITES_V1`, `QHP_SHARED_GRADE_WRITES_V1` and `QHP_SEMESTER_STORES_V1` must all be true for semester separation. Their default remains off. The existing two receipt/version tables from PR #55 must be installed in the isolated test database before testing the new writers. No request-time table creation or production migration is performed here.

Deploying this frontend without the corresponding protocol and switches deliberately leaves attempted shared writes unconfirmed; it must not be presented as a compatible legacy release. Test main-only rollout as one coordinated candidate after all safety gates. Do not enable the flags on m1 or m2.

## Validation and remaining limits

`tests/semester-shared-sessions.cjs` runs actual PHP HTTP handlers with two isolated browser outboxes and synthetic data. `tests/shared-store-client.cjs` exercises actual scientific save wrappers, stale displayed-period mutations, read-only history projection and deterministic notification read state. `tests/academic-transition.php` injects late academic/receipt failures through the actual handler and tests exact rollback and immutable replay. Native CI runs MySQL 8 / MariaDB 11.8 concurrent first-slot writes and simultaneous transition approval, plus late CHECK failures. Relevant prior grade, plan/profile and catalog tests are retained because those code paths changed.

Still outside completed acceptance: restoring the latest production archive into the independently credentialed Hostinger test database; proving actual msht.io/m1/m2 vhost roots; cross-device notification delivery through real hosting sessions; final-plan graduation without a successor; arbitrary offline transition recovery after both response attempts and browser closure; the remaining transfer and daily-report workflows. No synthetic test substitutes for those production/test-host checks.
